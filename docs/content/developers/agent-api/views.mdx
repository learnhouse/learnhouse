# Views

When Atlas has numbers, a list, a plan or a quiz to show, it doesn't only write prose: it returns a **view**, a small
JSON document of typed components that LearnHouse draws as tables, charts, timelines, flashcards and so on. The Agent
API hands you the same views, validated on the server, so you can draw them with your own components.

Views are sent in the `views` output mode (the default for agents that support them) as
[`view` events](/developers/agent-api/events#view), and kept in each message's `views`. In `markdown` mode you get
each view's Markdown fallback in the text instead.

## The view envelope

```json
{
  "id": "view_…",
  "call_id": "call_1",
  "schema_version": 1,
  "title": "Course completion",
  "layout": "stack",
  "components": [
    { "type": "kpis", "items": [{ "label": "Learners", "value": 1240, "delta": 4.5 }] },
    {
      "type": "table",
      "columns": [{ "key": "name", "label": "Course" }, { "key": "rate", "label": "Completion", "format": "percent" }],
      "rows": [{ "name": "Python 101", "rate": 62, "_link": { "kind": "course", "uuid": "course_x" } }]
    }
  ],
  "fallback_markdown": "- **Learners**: 1240 (+4.5%)\n\n| Course | Completion |\n| --- | --- |\n| Python 101 | 62% |"
}
```

| Field | | |
| --- | --- | --- |
| `id` | string | |
| `call_id` | string or null | The tool call that produced it, when there is one |
| `schema_version` | number | Version of the component schemas (currently `1`) |
| `title` | string or null | Heading over the whole view |
| `layout` | `stack` or `grid` | `grid` puts small components side by side on wide screens |
| `components` | Component[] | 1 to 12 components, each with a `type` |
| `fallback_markdown` | string | The same data as Markdown |

A view is at most 64 KB of JSON. Tables and charts hold up to 200 rows; most other lists are capped lower (see each
type below).

## Rendering views

- Switch on `type` and draw each component with your own UI.
- For a `type` you don't support (or don't support yet), render `fallback_markdown` for the whole view, or the
  component's own text. Never fail on an unknown type: new types can be added in a later `schema_version`.
- Components are validated and cleaned on the server: strings are length-limited and control characters removed,
  enums are normalized, links are checked. Still treat every string as text, not HTML.
- `<AgentChat />` in `@learnhouse/react` (and the Vue wrapper) has built-in renderers for the common types (kpis, table,
  chart, cards, timeline, steps, callout, text, checklist, progress, comparison, code, quiz, choices, glossary) and shows
  `fallback_markdown` for the rest. Override any type with your own component through `renderers`.

### Links

Items that point somewhere carry a link:

```json
{ "kind": "course", "uuid": "course_x" }
{ "path": "/dash/courses" }
```

`kind` is one of `course`, `chapter`, `activity`, `user`, `member`, `path`, `community`, `discussion`, `board`,
`assignment`, `submission`, `usergroup`, `live_session`, `podcast`, `playground`, `play`, `folder`, `scheduled_agent`,
`offer`. Map `kind` + `uuid` to a page in your app. `path` is a relative path on the LearnHouse site. Table rows use a
`_link` cell with the same shape.

### Fields the server fills in

Some fields come from LearnHouse, not from the model, and are only there for display: `image` (a cover or avatar URL on
`gallery`, `cards`, `leaderboard` and `profile` items), `doc`, `course_uuid` and `truncated` on `page` (the lesson
content as LearnHouse editor JSON, read from the real activity), `scale` on `gantt` and `calendar_start` on
`heatmap`.

### Practice components

`quiz`, `flashcards`, `matching`, `ordering`, `fill_blanks` and `whatif` are interactive. The answers are in the
props (`correct`, the order of `ordering.items`, the `[[answers]]` in `fill_blanks.text`): shuffle and hide them in
your UI, and check answers in the browser. Nothing is sent back to LearnHouse.

`choices` holds next-step buttons: when one is clicked, send its `prompt` as the next user message.

## The schema endpoint

`GET /api/v1/agent/views/schema` returns the exact JSON Schema of a view and of every component. Use it to generate
types or to validate views in your tests.

```json
{
  "version": "2026-11-16",
  "schema_version": 1,
  "view_schema": { "...": "JSON Schema of the view envelope" },
  "components": {
    "kpis": {
      "group": "data",
      "description": "1-8 headline numbers with optional % change.",
      "json_schema": { "...": "JSON Schema of the component" },
      "example": { "type": "kpis", "items": [{ "label": "Learners", "value": 1240, "delta": 4.5 }] }
    }
  },
  "types": ["kpis", "table", "chart", "..."]
}
```

<Callout type="info">
  The tables below are generated from the same models. Types are written TypeScript-style: `field?` is optional,
  `a|b` is one of the values, `str`, `num`, `int` and `bool` are JSON types.
</Callout>

## Component catalog

The 42 types, in four groups:

- **Data**: `kpis`, `table`, `chart`, `funnel`, `heatmap`, `cohort`, `radar`, `gauge`, `leaderboard`, `sparklines`,
  `geo`, `matrix`, `progress`, `comparison`
- **Structure**: `timeline`, `steps`, `flow`, `tree`, `mindmap`, `gantt`, `kanban`, `checklist`, `outline`
- **Content**: `page`, `diff`, `math`, `code`, `email`, `profile`, `rubric`, `glossary`, `gallery`, `cards`,
  `callout`, `text`
- **Practice**: `quiz`, `flashcards`, `matching`, `ordering`, `fill_blanks`, `whatif`, `choices`

Every component except `text` also takes an optional `title`, a heading over that component.
