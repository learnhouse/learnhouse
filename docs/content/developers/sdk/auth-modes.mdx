# Auth modes

Every request carries at most one credential. Which one decides what the API lets you do.

| Mode | How the client gets it | Acts as |
| --- | --- | --- |
| **Anonymous** | No `token`, `getToken` or `session` | A visitor: public courses only |
| **User session** | `credentials: 'include'` (the `LH_access` cookie on the instance's domain), or `token` / `getToken` with an access token from `auth.login()` | That user, with their roles in each org |
| **API token** | `token: 'lh_…'`, on a server | The organization, with the token's rights, capped by its creator's role |
| **Embed session** | `session` / `getSession` with a token from `embed.createSession()` | One learner, inside one org, on the embed routes only |

A cookie session and a bearer user token are the same mode: the API treats them identically. The tables below call
both **Session**.

<Callout type="info">
  The tables were checked against a running API (OSS, single organization) with the SDK's integration suite and a probe
  of each method in each mode. "Yes" means the API accepts the credential; the user still needs the right role for the
  data (RBAC applies on top). On LearnHouse Cloud some resources also need a plan: certificates and learning paths
  (Pro), communities and user groups (Standard), the Admin API and API tokens (Pro).
</Callout>

What a refused mode returns:

| Situation | Status | `err.code` |
| --- | --- | --- |
| No credential on a route that needs one | `401` | `HTTP_ERROR` |
| API token on a session-only route (accounts, progress, notifications…) | `403` | `HTTP_ERROR` (detail says API tokens are not allowed) |
| Embed session outside the embed routes | `403` | `EMBED_SESSION_ROUTE_NOT_ALLOWED` |
| Embed session for another organization | `403` | `SESSION_NOT_BOUND_TO_ORG` |
| User session on the Admin API | `403` | `HTTP_ERROR` |

## Content

| Method | Anonymous | Session | API token | Embed |
| --- | --- | --- | --- | --- |
| `orgs.get`, `orgs.getByUuid` | Yes | Yes | **No** (403) | Yes |
| `orgs.resolveDomain` | Yes | Yes | Yes | Yes |
| `courses.list`, `courses.listAll`, `courses.count`, `courses.search` | Yes (public courses) | Yes | Yes | No |
| `courses.get`, `courses.getById`, `courses.getMeta` | Yes (public courses) | Yes | Yes | Yes |
| `courses.listUpdates` | Yes | Yes | Yes | No |
| `chapters.get`, `activities.listForChapter` | Yes | Yes | Yes | No |
| `chapters.listForCourse`, `activities.get`, `activities.getById`, `activities.resolve` | Yes | Yes | Yes | Yes |
| `search.org`, `search.orgPages` | Yes | Yes | Yes (`search` right) | No |
| `podcasts.*` | Yes (public podcasts) | Yes | Yes | No |
| `instance.info` | Yes | Yes | Yes | Yes |

<Callout type="warning">
  `orgs.get()` refuses API tokens: the organizations router only takes user sessions. On a server, read the org's
  courses directly with `courses.list(orgSlug)`; `auth.me()` tells you the token's `org_id` and `org_slug`.
</Callout>

`lh.agent` (Atlas, the learner copilot, custom agents) is an Enterprise feature with its own rules; see
[Agent API security](/developers/agent-api/security). Embed sessions reach the learner side of it.
