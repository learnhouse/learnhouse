## What to build
<Describe your product: who it is for, the main screens, the look and feel. Example: "A mobile-first microlearning app for retail staff: today's lesson, a 3-question quiz, a streak.">

## Stack
- Next.js (App Router) + TypeScript. Plain CSS or Tailwind.
- Server-only environment variables: LEARNHOUSE_URL, LEARNHOUSE_TOKEN (an lh_ org API token, optional for public courses), LEARNHOUSE_ORG_SLUG.
- npm packages: @learnhouse/sdk (typed API client) and @learnhouse/react (renders lessons with LearnHouse's own blocks). Install the version that matches the LearnHouse instance.

## Data (server side, with @learnhouse/sdk)
- const lh = createClient({ baseUrl: process.env.LEARNHOUSE_URL, token: process.env.LEARNHOUSE_TOKEN })
- Courses: lh.courses.list(orgSlug, { limit: 50 })
- Course tree (chapters, activities): lh.courses.getMeta(courseUuid, { slim: true })
- A lesson with its content: lh.activities.get(activityUuid)
- Search: lh.search.org(orgSlug, query)
- Media URLs: lh.media.* helpers
- Never send the token to the browser. Fetch in Server Components or route handlers.

## Lessons (client side, with @learnhouse/react)
- Import '@learnhouse/react/styles.css' once.
- Render a lesson fetched on the server: <LearnHouseActivity activity={activity} courseId={courseUuid} baseUrl={LEARNHOUSE_URL} />
- Match the product's look with theme={{ accent, fontFamily, radius, contentWidth }}, and replace blocks with components={{ blockQuiz: MyQuiz }} when needed.
- Use onEvent (load, ready, complete, media...) for analytics and progress.

## Learner state
An lh_ API token acts for the organization, not a learner. Keep progress in your app (localStorage for a prototype, your database for production), or sign learners in to LearnHouse and use lh.trail.completeActivity with their own token.

## Quality bar
Responsive down to 375px, keyboard accessible, real loading/empty/error states, no placeholder text: use the real courses from the API.

Docs: https://docs.learnhouse.app/developers`
