# CLI Reference

Overview of the LearnHouse CLI commands for running a self-hosted instance. The CLI is published as `learnhouse` on npm and is typically run with `npx learnhouse`.

<Callout type="info">
This page is a summary. See [CLI Commands](/cli/commands) for every flag and the exact behavior of each command.
</Callout>

## Choosing an installation

Every command acts on one installation: the directory passed with `--dir` (or `LEARNHOUSE_DIR`), else the current directory if it holds one, else the installation under `~/.learnhouse`. With several installations, pass `--dir`:

```bash
npx learnhouse --dir ~/.learnhouse/production status
```

## Setup and Configuration

### `learnhouse setup`

Run the interactive setup wizard. It generates `docker-compose.yml`, `.env`, `learnhouse.config.json`, and an nginx or Caddy configuration in `~/.learnhouse/<name>`, then offers to start the instance.

```bash
npx learnhouse@latest setup
```

Use `--ci` with flags (`--name`, `--domain`, `--port`, `--admin-email`, `--admin-password`, `--org-name`, `--org-slug`, `--channel`, `--external-db`, `--external-redis`, `--no-start`, and more) for a non-interactive setup.

Re-running setup on an existing installation reconfigures it in place and keeps its deployment ID, database password, secrets and app image.

### `learnhouse config`

Show the installation's version, directory, edition, URL and organization slug.

```bash
npx learnhouse config
```

### `learnhouse env`

Interactively edit the variables in your `.env` file by category (Domain & Hosting, Database & Redis, Security, AI, Email, S3 Storage, OAuth), then optionally restart services.

```bash
npx learnhouse env
```

<Callout type="info">
The `env` command edits a curated set of variables. Edit `.env` directly for anything else, such as the [AI provider settings](/self-hosting/configuration/ai-setup), then run `npx learnhouse start` to recreate the changed containers.
</Callout>

## Service Management

### `learnhouse start`

Start all LearnHouse services. On first run, this pulls the required Docker images.

```bash
npx learnhouse start
```

### `learnhouse stop`

Stop all running LearnHouse services. Containers and data volumes are kept.

```bash
npx learnhouse stop
```

### `learnhouse status`

Show the URL and the status of each LearnHouse service.

```bash
npx learnhouse status
```

### `learnhouse logs`

Stream container logs for all services.

```bash
npx learnhouse logs
```

### `learnhouse update`

Update LearnHouse to the latest release or a specific version. Backs up the database, pulls the new image, runs database migrations before the new version starts, and restarts services. See [Updates](/self-hosting/maintenance/updates).

```bash
npx learnhouse update
npx learnhouse update --to 1.4.2
npx learnhouse update --no-migrate    # skip migrations
npx learnhouse update --no-backup     # skip the pre-upgrade backup
```

## Diagnostics

### `learnhouse doctor`

Run diagnostics: Docker, container state and restarts, port, DNS, disk space, recent log errors, and `.env` validation.

```bash
npx learnhouse doctor
```

### `learnhouse health`

Run health checks: containers, PostgreSQL, Redis, the HTTP health endpoint, disk, and resource usage.

```bash
npx learnhouse health
```

### `learnhouse shell`

Open an interactive shell inside a running container for debugging.

```bash
npx learnhouse shell
```

## Resources

### `learnhouse deployments`

List the LearnHouse deployments on this machine, or set memory limits.

```bash
npx learnhouse deployments
```

### `learnhouse scale`

Set a memory limit for each service.

```bash
npx learnhouse scale
```

## Backup and Restore

### `learnhouse backup`

Create an archive with a database dump, a copy of `.env`, and uploaded content. Archives are written to `<installDir>/backups/`.

```bash
npx learnhouse backup
```

### `learnhouse restore`

Restore a backup archive, or a pre-upgrade dump written by `update`.

```bash
npx learnhouse restore backups/learnhouse-backup-<timestamp>.tar.gz
```
