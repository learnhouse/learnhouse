# Grading & Submissions

## How a grade is calculated

Each task is scored out of 100. The assignment grade is the average of its task scores, as a percentage. The **Grading Type** only changes how that percentage is shown to learners.

## Grading types

| Grading Type | Shown as | Passes by default at |
| --- | --- | --- |
| **Alphabet** | A (90% and up), B (80%), C (70%), D (60%), F | 60% |
| **Numeric** | A score from 0 to 100 | 50% |
| **Percentage** | A percentage | 50% |
| **Pass / Fail** | Pass or fail | 50% |
| **GPA Scale** | A 4.0 scale, from 4.0 (93% and up) down to 0.0 | 60% |

Set **Passing threshold** in the assignment settings to use a different pass mark.

## Automatic grading

Quiz, Form, Code, Short answer and Number answer tasks are graded automatically. File submission tasks always need a teacher.

With **Automatic grading** turned on, a learner's submission is graded and the activity is marked complete the moment they submit. This is only possible when the assignment has no File submission task. You can still change the grade by hand afterwards.

Without it, open the submission and click **Run Auto-grade** on a task to score it.

## The Submissions tab

The **Submissions** tab lists every learner who started or submitted the assignment, with their status:

| Status | Meaning |
| --- | --- |
| **In progress** | The learner has saved work but not submitted. |
| **Submitted** | Submitted and waiting for a grade. |
| **Late** | Submitted after the due date. |
| **Graded** | A grade has been recorded. |

Search by name or email, filter by status, and sort by **Date submitted**, **Student name**, **Status**, **Grade**, **Needs grading first**, **Late submissions first** or **Recently graded first**.

## Grading a submission

Click **Evaluate** on a submission. For each task you see what the learner handed in, the task's hint and reference document, and the current grade.

- Enter a score out of 100, or use **Full**, **Half** or **Zero**.
- Add a note for the task. It is saved with the grade.
- For a file submission, download the file, review it, and enter the grade.
- Write **Overall feedback** for the whole submission. The learner sees it next to their grade.

<img src="/img/pages/assignments/assignment-evaluate.webp" alt="The Evaluate dialog showing the current grade, Passing, and a quiz task with each answer marked true or false" width={1600} height={900} style={{ borderRadius: 10 }} />

The header shows the **Current grade** and whether it is **Passing** or **Not passing**. Then pick an action:

| Action | What it does |
| --- | --- |
| **Set final grade** | Calculates and saves the grade without completing the activity. |
| **Finalize & Complete** | Sets the final grade and marks the activity as done for the learner. |
| **Reject Assignment** | Deletes the submission so the learner can submit again. |

<Callout>
Graded assignments count toward [course certificates](/platform/certifications): every graded assignment must be passed before a certificate is issued.
</Callout>

## Retries

With **Allow retries** on, a learner whose submission is graded can click **Try again**. Their answers are wiped, the attempt counter goes up, and the next grade replaces the previous one. No history of earlier attempts is kept. **Maximum attempts** caps the total, with `0` meaning unlimited.

## Not grading at all

An assignment can opt out of grading entirely. See [Formative Assessment](/platform/assignments/formative): the learner hands work in, receives the model answer, and no grade is ever recorded.
