# Roles and Permissions

Every member has exactly one role in each organization they belong to. A role is a permission matrix: for each resource (courses, users, user groups and so on) it says whether the member can create, read, update or delete, and whether that applies to everything or only to items they own.

## Default roles

Every instance ships with four roles. They are marked **System-wide** in the dashboard and cannot be edited or deleted; use **View Rights** to see their permissions.

| Role | Description |
| --- | --- |
| **Admin** | Full platform control |
| **Maintainer** | Mid-level manager, wide permissions but no platform control |
| **Instructor** | Can manage their own content |
| **User** | Read-only learner. The default role for new members. |

### What each default role can do

C = create, R = read, U = update, D = delete. "own" means only items the member created.

| Resource | Admin | Maintainer | Instructor | User |
| --- | --- | --- | --- | --- |
| Courses | C R U D | C R U D | C R, U own, D own | R |
| Chapters and activities | C R U D | C R U D | C R | R |
| Assignments | C R U D | C R U D | C R U | R |
| Users | C R U D | C R U | none | none |
| User groups | C R U D | C R U D | R | R |
| Folders and media | C R U D | C R U D | C R | R |
| Organization | C R U D | R | none | none |
| Roles | C R U D | R | none | none |
| Communities | C R U D | C R U D | R | R |
| Discussions | C R U D | C R U D | C R, U own, D own | C R, U own, D own |
| Podcasts, boards, playgrounds | C R U D | C R U D | C R, U own, D own | R |
| Dashboard access | Yes | Yes | Yes | No |

In practice:

- **Admins** manage everything, including organization settings, roles, sign-in and two-factor policies.
- **Maintainers** run the organization day to day: content, members and groups. They cannot change organization settings or roles, and cannot delete users.
- **Instructors** create courses and other content and manage what they own. They cannot manage members.
- **Users** take courses, join discussions and track their progress. They have no dashboard.

Some settings are restricted to the Admin role specifically, such as the [sign-in methods and two-factor policy](/platform/users/two-factor). Analytics and other "organization admin" features check for permission to update the organization, which only Admin has among the defaults.

## Custom roles

<Callout type="info">
Custom roles need the **Pro** plan or higher on LearnHouse Cloud. They are included on every self-hosted instance.
</Callout>

Go to **Users** → **Roles** and click **Create a Role**.

1. Enter a **Role Name** (at least 2 characters) and a **Description** (at least 10 characters).
2. Optionally start from one of the **Predefined Rights**: Admin, Maintainer, Instructor, Viewer, Content Creator, User Manager, Moderator, Analyst or Guest. A preset only fills in the checkboxes; you can change them afterwards.
3. Under **Permissions**, tick the actions the role should have for each resource: Courses, Users, User Groups, Folders, Media, Organizations, Course Chapters, Activities, Roles and Dashboard. Actions are **create**, **read**, **read own**, **update**, **update own**, **delete** and **delete own**. Dashboard only has **access**.
4. Save. The role now appears in the role dropdown on the **Users** tab.

Custom roles belong to your organization. Deleting a role cannot be undone, and members who had it lose its permissions.

## Admin seats

On LearnHouse Cloud, every member whose role has dashboard access takes an admin seat. See [member limits](/platform/users#member-limits-on-learnhouse-cloud).
