# Multi-Tenancy

A LearnHouse instance can host one organization or many. Each organization works like its own platform, with its own courses, members, settings and branding, while sharing one deployment and one database.

## Who gets what

| Deployment | Organizations |
| --- | --- |
| LearnHouse Cloud | The platform is multi-tenant. Anyone can create organizations, on any plan. |
| Self-hosted, open source | One organization. Creating a second one is refused with "Multi-organization mode requires Enterprise Edition". |
| Self-hosted, Enterprise Edition | As many organizations as you need. |

<Callout type="info">
Running several organizations on a self-hosted instance needs a valid [Enterprise Edition](/enterprise) license.
</Callout>

## Enabling multi-organization mode

On an Enterprise Edition instance, set `LEARNHOUSE_TENANCY=multi` on the API. Each organization is then served on its own subdomain of your `LEARNHOUSE_DOMAIN` (for example `myschool.example.com`), or on its own [custom domain](/platform/organizations/custom-domains). With `LEARNHOUSE_TENANCY=single`, the instance serves one organization at the root of your domain.

Create new organizations from the [admin dashboard](/platform/organizations/admin-dashboard) with **New organization**.

See [Environment Variables](/self-hosting/configuration/environment-variables) for the related settings.

## Accounts across organizations

One account can belong to several organizations, with a different role in each. Members can switch between their organizations from the organization switcher. Removing someone from one organization does not affect their account or their other memberships.

## Data isolation

Every record is tied to an organization, and every query is scoped to it. One organization cannot read another's courses, members or settings.
